# Конвеєр безперервної інтеграції (CI/CD) проєкту «PythonStart»

## 1. Призначення автоматизованого конвеєра
У проєкті «PythonStart» налаштовано автоматизований конвеєр безперервної інтеграції (Continuous Integration) на базі хмарного сервісу **GitHub Actions** (файл `.github/workflows/ci.yml`). Його головна мета — автоматично перевіряти кожну зміну коду перед її влиттям до головної гілки `main`.

## 2. Етапи автоматичної перевірки (Jobs & Steps)
При кожному відкритті або оновленні `Pull Request` віртуальний сервер `ubuntu-latest` виконує такі кроки:
1. **Checkout (`actions/checkout@v4`)** — завантаження актуального стану гілки розробника.
2. **Setup Node.js (`actions/setup-node@v4`)** — розгортання середовища виконання Node.js версії 20.
3. **Install Dependencies (`npm install`)** — встановлення пакетів тестового середовища з `package.json`.
4. **Static Analysis (`npm run lint`)** — запуск скрипту `scripts/lint-check.js`, який перевіряє наявність усіх архітектурних модулів, відсутність нерозв'язаних маркерів конфлікту Git (`<<<<<<<`) та забороненої функції `eval()`.
5. **Unit Testing (`npm test`)** — автоматичний прогін усіх модульних тестів Vitest із папки `tests/`.

## 3. Правила дій розробника у разі падіння конвеєра (CI Failed)
- Злиття (Merge) запиту на злиття з червоним статусом перевірки (`Checks failed`) технічно заблоковано правилами захисту гілки `main`.
- Автор Pull Request зобов'язаний відкрити вкладку **Checks / Details** на GitHub, прочитати журнал помилки (лог консолі), виправити код локально у VS Code, перевірити його командою `npm run ci:check` та відправити новий коміт у ту саму гілку.
