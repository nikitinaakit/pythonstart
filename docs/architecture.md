# Модульна архітектура та командний процес «PythonStart»

## 1. Принцип побудови застосунку
Клієнтський вебзастосунок розроблено за принципом єдиної відповідальності (SRP): кожен модуль виконує лише одну логічну функцію. Дані відокремлені від відображення, а тексти інтерфейсу винесені в словник локалізації.

## 2. Призначення основних модулів

| Модуль / Файл | Зона відповідальності | Відповідальний у команді |
|---|---|---|
| data/topics.js | Зберігання структурованого масиву навчальних тем і завдань з Python | Учасник 2 |
| js/messages.uk.js | Словник текстових повідомлень українською мовою | Учасник 3 |
| js/i18n.js | Функція отримання перекладу t(key) за ключем | Учасник 3 |
| js/validation.js | Чиста логіка перевірки відповіді учня та обробки порожнього поля | Учасник 4 |
| js/app.js | Головна точка ініціалізації та об’єднання модулів | Учасник 1 |

## 3. Правила командної роботи (Feature Branch Workflow)
1. Прямі коміти у гілку main заборонені.
2. Кожне завдання виконується в окремій гілці feature/номер-назва або docs/номер-назва.
3. Злиття у main відбувається виключно через Pull Request після взаємної перевірки (Code Review).

## 4. Алгоритм вирішення конфліктів злиття (Merge Conflicts)
Якщо під час виконання git merge origin/main виник конфлікт у спільному файлі:
1. Відкрити конфліктний файл у VS Code та проаналізувати блок поточних змін (<<<<<<< HEAD) і вхідних змін (>>>>>>> origin/main).
2. Узгодити правильний код з автором суміжної гілки.
3. Повністю видалити службові маркери <<<<<<<, =======, >>>>>>> і зберегти чистий код (Ctrl + S).
4. Виконати git add <файл>, завершити злиття командою git commit і відправити зміни через git push.
