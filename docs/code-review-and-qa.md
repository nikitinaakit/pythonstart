# Регламент інженерної інспекції коду (Code Review) та контролю якості (QA) проєкту «PythonStart»

## 1. Правила проведення Code Review у команді
1. Жоден учасник команди не зливає (Merge) власний Pull Request у гілку `main` без перевірки щонайменше одним рецензентом.
2. Рецензент перевіряє зміни у вкладці **Files changed** за 4 критеріями:
   - **Чистота коду:** зрозумілі імена функцій та змінних, дотримання принципу єдиної відповідальності (SRP), відсутність «магічних чисел».
   - **Інформаційна безпека:** заборона вставки необробленого користувацького вводу через `innerHTML` (захист від XSS), відсутність секретних ключів у коді.
   - **Крайові випадки (Edge Cases):** безпечна обробка порожніх рядків, `null`, `undefined`, пошкодженого JSON у `localStorage`.
   - **Тестове покриття:** наявність актуальних модульних тестів у папці `tests/` та успішний статус `npm test`.

## 2. Етика написання коментарів рецензента
- Критикуємо програмний код і технічне рішення, а не особистість автора.
- Кожен зауважений недолік супроводжуємо конкретною пропозицією виправлення.

## 3. Класифікація дефектів (Bug Reports) у GitHub Issues
| Параметр | Рівні | Пояснення для проєкту «PythonStart» |
| :--- | :--- | :--- |
| **Severity (Серйозність)** | `Critical`, `Major`, `Minor` | Технічний вплив помилки на працездатність тренажера та збереження прогресу учня. |
| **Priority (Пріоритет)** | `High`, `Medium`, `Low` | Терміновість усунення помилки перед релізом MVP v1.0 на GitHub Pages. |
