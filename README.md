
# Навчальний вебтренажер «PythonStart»

![CI Status](https://github.com/nikitinaakit/pythonstart/actions/workflows/ci.yml/badge.svg)

## 1. Загальна інформація про проєкт

Програмний продукт розробляється в межах вивчення освітнього компонента «Командна розробка програмних проєктів».

PythonStart — інтерактивний клієнтський вебзастосунок для вивчення базових конструкцій мови програмування Python учнями 8–9 класів закладів загальної середньої освіти (ЗЗСО).

## 3. Освітня проблема та цільова аудиторія

- **Освітня проблема:** Складність первинного опанування текстового коду здобувачами без попереднього досвіду програмування.
- **Цільова аудиторія:** Учні 8–9 класів на уроках інформатики та під час самостійної підготовки вдома, а також учителі інформатики.
- **Формулювання проблеми (Problem Statement):** Учні під час переходу до текстового програмування мовою Python часто припускаються синтаксичних помилок і втрачають мотивацію через складність перших кроків у програмуванні.

## 4. Мета проєкту та межі першої версії (MVP)

**Мета:** Створити інтерактивний навчальний тренажер PythonStart для закріплення базових тем програмування мовою Python.

**Реалізовано у першій версії:**
- Каталог базових навчальних тем.
- Теоретичні матеріали та приклади коду.
- Інтерактивні вправи з миттєвою перевіркою відповідей.
- Підказки та діагностика типових помилок.
- Збереження навчального прогресу.

**Не входить до першої версії:**
- Складна реєстрація користувачів.
- Серверна база даних.
- Інтеграція зі шкільним електронним журналом.

## 6. Основні можливості релізу MVP v1.0.0

**Реалізовано у версії v1.0.0:**

1. **Каталог із 4 базових тем Python:** «Змінні та типи даних», «Умовний оператор if», «Цикл for та функція range()», «Списки (list) та індексація».
2. **Миттєвий пошук і фільтрація:** пошук за назвою чи описом теми та фільтрація за статусом опрацювання.
3. **Інтерактивне робоче поле:** перевірка введеної відповіді, діагностика типових помилок і дружні пояснення українською мовою.
4. **Автоматичне збереження прогресу:** збереження пройдених тем і набраних балів у браузері за допомогою `localStorage`.
5. **Інтеграція із зовнішнім REST API:** блок «Порада дня з Python» і статистика репозиторію GitHub API з резервними локальними даними (Fallback).

**Відомі обмеження поточної версії:**

- Відсутня серверна база даних і централізований кабінет учителя. Прогрес зберігається локально в браузері конкретного пристрою.
- Перевіряються короткі фрагменти коду та результати виконання без запуску повноцінного серверного інтерпретатора Python.

## 9. Інструкція локального запуску та перевірки якості

1. Клонуйте репозиторій на свій комп'ютер та перейдіть у папку проєкту:

   ```bash
   git clone https://github.com/nikitinaakit/pythonstart.git
   cd pythonstart
   ```

2. Встановіть залежності для тестування (потрібен встановлений Node.js версії 18+ або 20+):

   ```bash
   npm install
   ```

3. Запустіть перевірку якості коду (статичний лінтер і модульні тести Vitest):

   ```bash
   npm run lint
   npm test
   npm run ci:check
   ```

4. Для відкриття вебінтерфейсу у браузері відкрийте папку в редакторі VS Code та запустіть Live Server на файлі `index.html`.

Детальний опис конвеєра CI/CD наведено у файлі [docs/ci-cd-pipeline.md](./docs/ci-cd-pipeline.md).

## 11. Організація командної роботи

- **Проєкт:** Навчальний тренажер «PythonStart».
- **Інструмент керування завданнями:** GitHub Issues та GitHub Projects.
- **Посилання на Kanban-дошку:** [PythonStart – Team Board](https://github.com/users/nikitinaakit/projects/2/views/1).
- **Контрольний етап:** [Milestone MVP v1.0](https://github.com/nikitinaakit/pythonstart/milestone/1).

### Kanban-статуси дошки

- **Backlog** — усі заплановані роботи та ідеї.
- **To do** — відібрані завдання для найближчого виконання.
- **In progress** — завдання, що перебувають у роботі.
- **Review** — перевірка отриманого результату іншим учасником команди.
- **Done** — критерії прийнятності повністю виконані та перевірені.

### Правила команди

1. Кожне завдання (Issue) має чіткий опис, критерії прийнятності та одного відповідального виконавця (Assignee).
2. Для всіх завдань визначаються тип роботи і пріоритет за допомогою міток (Labels).
3. Завдання першої версії продукту об'єднуються контрольним етапом **Milestone MVP v1.0**.
4. Перед переходом у статус `Done` результат перевіряє інший член команди на етапі `Review`.
5. Зміни статусів на дошці мають відповідати фактичному стану виконання роботи.
